## Security review and remaining dependencies

The frontend review inspected the theme storage and URL allowlist, dynamic HTML
highlighting, Markdown rendering, image/link components, content API boundaries,
and workflow permissions. `v-html` receives highlight.js output from repository
content; the site has no public content editor or deployed runtime API. No new
confirmed high or critical issue was found in these paths. This is a source and
local-output review, not a production penetration test or a verification of edge
headers and hosting permissions.

LL04 evidence comes from the locked dependency graph and the current registry
audit response:

- [minimatch GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)
  reports pattern amplification when optimization level is at least 2; the listed
  fix starts at 11.0.1. The locked versions are pulled through lint tooling and
  Nitro's build dependencies.
- [glob GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4)
  reports continued traversal after cancellation; the listed fix starts at
  14.0.2. The locked versions come through Nitro's `@vercel/nft` and archiver
  dependencies.

An exploit against this trusted-content static site was not demonstrated.
Upgrading all affected versions crosses major-version contracts in their
parents. Supported upstream upgrades and compatibility validation remain a
follow-up. The existing two low matches in KaTeX and deepmerge also remain.
`pnpm audit --audit-level high` exits successfully with two low and five moderate
matches and no high or critical matches. The high-severity CI threshold is
unchanged; a passing gate does not mean an advisory-free graph.

## Validation

The repository's locked Node 22.22.3 / pnpm 10.27.0 dependencies were installed
independently in this worktree. Lint, typecheck, seven Node behavior tests,
content validation, all 104 image rendition checks, and production build were
run. Browser verification uses the repository's Playwright 1.64.1 configuration
and matching installed Chromium headless shell, serving built static output.
All 25 static-output browser tests and four injected-upstream-failure tests pass.

The browser suite adds four theme cases: failed selection with later recovery
and a non-Paper fallback, unavailable startup preference, a delayed request
superseded by a newer choice, and reopening the picker during a failed request.
Existing malformed-storage tests now wait for the selected stylesheet to load
before inspecting persisted storage. No arbitrary sleep replaces these checks.

Independent standards and scope reviews both caught an intermediate-state gap:
reopening the picker during a pending request reported the requested theme as
current before it had loaded. The strengthened reopening test reproduced it.
The runtime now reports the applied theme until loading succeeds, keeping
appearance, selection, and storage consistent during the pending interval too.

Initial verification exposed a minimal DOM fixture that did not model stylesheet
completion, premature storage assertions, and an incorrect expected Nord color
in the new test. These were corrected; they were not application failures in the
baseline. The failed-theme test separately reproduced the actual baseline bug.

The production build retains the previously documented uppercase-PDF link
warning. Its existing exact-case URL is preserved. Browser coverage remains
Chromium; Firefox, Safari, assistive technology, live hosting, deployment and
rollback remain unverified. No content, logo, generated images, dependencies,
hosting settings, or live data are changed by this PR.

## Manual review

With the documented toolchain installed, run `pnpm build`, then `pnpm test:e2e`.
The four new cases should pass. For a visual check, run `pnpm dev`, open the site,
and select a different theme. Block that theme's stylesheet in browser network
tools and try it again from another working theme. The working palette and
selected button should remain consistent; unblocking the request should allow
selection again. Keyboard selection, Escape, focus return, and persistence
should continue to work.
