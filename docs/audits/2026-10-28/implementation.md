## Implementation decisions and review

The theme catalog and selection policy have one owner in the parser-blocking runtime. A static Paper stylesheet appears before that runtime. Native dialogs own modality and focus; Vue owns mounting and unmounting. A generated frontend image manifest avoids the SSR bundler's shared-JSON externalization issue. These are small changes to the existing publishing architecture.

The initial retry implementation passed development checks but still called absent APIs in static output. Independent review identified that gap. The final retry reloads the prerendered document. A separate helper treats a production-client fallback API 404 as an unavailable payload, while direct missing pages and development-server 404s retain their meaning.

One flaky modal observation treated a hidden accessibility role as proof of component removal. The [HTML dialog close algorithm](https://html.spec.whatwg.org/multipage/interactive-elements.html#close-the-dialog) restores focus before queuing the close event. The test now waits for the dialog element to be removed before reopening it. This strengthens the lifecycle assertion instead of adding a timing delay.

The rendered Paper check also caught a real CSS-cascade issue that source color arithmetic missed. The [before](verification/contrast-before.log) and [after](verification/contrast-after.log) checks preserve that evidence. Current [mobile article](verification/mobile-article.png) and [theme picker](verification/theme-picker.png) screenshots were inspected.

Independent correctness review and a separate comment review were read-only. The final focused source review found no further actionable defects in the inspected content recovery, theme, image/dialog, and regression paths. It did not independently run the suite or exhaustively review every line of the dependency graph. Review used the configured `gpt-6.1-terra`; a different-family review was not substituted for the user's model preferences. No workspace transcript directory was supplied, so the decision trail was checked against saved command results and source rather than a complete transcript file. Cursor-only control and deslop tools were unavailable; direct Playwright verification and manual/independent diff review were used and are not described as execution of those tools.

The Prove It Works principle required production-output and rendered-color checks. Build the Lever produced the committed validators and regression suites. Model the Domain put theme validity under one owner. Sequence Work into Verifiable Units separated the content, browser, dependency, and recovery checks. Attack the Premise changed the flaky dialog observation after repeated failures. The [decision trail](decisions.tsv) records the material choices and corrections.

## Remaining limits

The final [dependency response](verification/dependency-after.json) contains two low-severity matches. KaTeX 0.16.47 remains in rehype-katex's supported 0.16 range; its advisory describes a trust bypass after existing prototype pollution. Deepmerge 4.3.1 appears in build tooling, and the captured advisory lists no patched release. These matches are not claimed fixed or proven harmless. No reachable public exploit was established in the current trusted-content static site. Avoiding an unsupported math override or a new bundler migration keeps these exceptions visible for follow-up.

The build still reports a link-style warning for the existing uppercase PDF URL. Its exact-case link works and has an accessible name. Renaming that public URL would require a deliberate compatibility decision. Build tooling also emits its own annotation/development-head diagnostics; these are distinct from failing application checks.

Production deployment identity, Cloudflare permissions, a real rollback, Safari/Firefox, assistive-technology behavior, and a visual/contrast review of every alternate palette remain unverified. The original image and document contents were not rewritten. There is no database backup claim because the site has no database.
